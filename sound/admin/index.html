Web Analytics
DNS Records Docs

Read the numbers as a floor, not a headcount. Because the beacon is cookieless there is no per-visitor identity, so “visits” are estimated from page views rather than counted people, and someone returning tomorrow is indistinguishable from a stranger. Ad and tracker blockers drop the beacon entirely, so real traffic is always somewhat higher than what you see — never lower.

It measures arriving, not listening. A page view cannot tell you which cassette anyone played, or whether they pressed play at all. That would need our own append-only event table writing a row per play, the same shape as game_events — deliberately not built, so don't read a listening story into a traffic chart.

Installed as a hand-placed JS snippet in assets/site-analytics.js rather than Cloudflare's automatic injection: thegamebureau.com is DNS-only on Cloudflare — the apex resolves to GitHub Pages and responses carry no cf-ray — so no request passes through the proxy that would otherwise inject it. Auto-injection would silently collect nothing.

What this is

A gift, not a product

Every city we run games in gets a 15-song cassette tape on /sound/ — hometown artists, songs that name the streets, the fight song the whole stadium knows, the record cut in a studio down the road. An AI agent builds a new one every morning on its own; this page is where you watch it happen and step in if you want to.

It makes us no money, and that's the point. Someone playing a game in New Orleans — or just thinking about it — can put the New Orleans tape on and feel the city before they ever arrive. Curiosity about a place is what we're really selling. The game is how somebody acts on it.

So songs are picked for “this makes me want to go there”, not for chart positions. A deep cut naming a neighbourhood beats a famous song by someone who merely happens to be from there.

How it works

Every morning, without you

A scheduled AI agent does the whole job at 6:30 AM Central and saves the result to the database. Nobody has to press anything.

  1. It reads the city list and the tapes we already have.
  2. It picks the next city with no tape, plus the emptiest existing tape to finish.
  3. It researches songs and checks every Spotify link is real by searching for it.
  4. It saves the songs and publishes them — the new tape is live on /sound/ immediately.

The Daily Routine card shows when it last succeeded. If that goes quiet for more than a day, something needs a look.

Your part

What a human can do

A song is wrong, or won't play

Use the Track Archive panel: find the song and press Archive. That hides it from /sound/ straight away and keeps it as a do-not-reuse tombstone for that city, so tomorrow's run cannot pick it again. Add a replacement so the tape still has 15 active songs. If the song is right but only will not play, clear its spotify_id in public.soundtrack_songs — the player falls back to a Spotify search for the artist and title.

I want a tape for a city right now

Open the routine and trigger a run, or copy the prompt below into any AI with web access. Both do the same work.

Someone emailed a song suggestion

They go to soundtrack@thegamebureau.com — see the Suggestions card. Treat them as leads worth checking, not as facts; the ID still has to be verified.

I want it to stop, or run at a different time

Open the routine and pause it or edit the schedule. Nothing here is load-bearing for the games — the tapes are a bonus feature.

Where are the rules written down?

In sound/README.md, next to the data. That file is written for both people and AI agents — it's what an agent reads before touching a tape.
